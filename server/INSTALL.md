# Домашнее хранилище смет

Это маленький сервер для компьютера, который иногда включён. Сайт на GitHub Pages считает смету в браузере. Сервер только хранит объекты, сметы и учётные записи. Склад, заявки и канбан сюда не входят.

Сервер сам никуда не подключается, порты не открывает и на чужой компьютер не ставится. Запуск на домашнем ПК — отдельный шаг.

## Что уже решено

- Одна общая база на всех вошедших пользователей этой бригады, не больше 10 человек. Так список объектов похож на общий список Remfy, а не на десять разных программ.
- Администратор заводит людей и снимает резервную копию. Обычный пользователь этого не может.
- Пароли хранятся как scrypt-хеш. Сессия — случайный ключ, в базе только его хеш. Ключ вводится в браузере и уходит только на указанный адрес сервера.
- Каждая карточка и каждая смета имеют номер версии. Если с другого устройства уже сохранили более новую версию, сервер отвечает отказом и не затирает ни свою, ни местную копию.
- Пока компьютер выключен, правка остаётся в браузере. Надпись говорит «сохранено на этом устройстве, ожидает отправки», а не «сохранено на сервере».

## Установка на Windows

1. Установите Node.js 22 или новее с https://nodejs.org (ветка LTS, если она уже 22+). Проверка: `node -v`.
2. Скопируйте папку `server` на компьютер. Рядом должен лежать файл `library.js` из корня сайта: сервер проверяет сметы тем же кодом. Проще скопировать весь проект, не только папку `server`.
3. В командной строке из папки `server` один раз задайте администратора. Пароль не записывайте в файлы проекта и не коммитьте:

```bat
set SMETA_ADMIN_USER=admin
set SMETA_ADMIN_PASSWORD=сюда-длинный-пароль
start.bat
```

Пароль не короче 10 символов. В журнале он не печатается. Повторный запуск не меняет уже созданный пароль.
4. Окно должно показать `http://127.0.0.1:8787`. Это только этот компьютер. Телефон его не видит, и это нормально на этом шаге.
5. На сайте откройте «Объекты», впишите адрес сервера и нажмите «Запомнить адрес», затем логин и пароль. Для проверки на том же ПК адрес: `http://127.0.0.1:8787`.

Нового человека заводит администратор запросом `POST /api/admin/users` с полями `username`, `password`, `role` (`user` или `admin`). Логин: латиница, цифры, точка, `_` или `-`, 3–32 знака. Одиннадцатый пользователь не создаётся.

Резервная копия: администратор нажимает не из сайта, а вызывает `POST /api/admin/backup` со своим ключом, либо копирует файл `server/data/smeta.sqlite`, пока сервер остановлен. Команда backup кладёт снимок в `server/data/backups/`. Папка `server/data` в git не входит.

Обычный перенос без сервера по-прежнему есть: «Скачать все объекты» и «Импорт JSON». Это файл, не синхронизация.

## Как телефону достучаться, когда решите открыть доступ

Сейчас сервер слушает только `127.0.0.1`. Чтобы телефон его видел, нужен отдельный шаг и ваше решение. Два спокойных варианта, аккаунты и туннели за вас не создавались:

- Tailscale: программа ставится на домашний ПК и на телефоны, трафик идёт через их сеть, порт на роутере не открывается. У компьютера появляется свой адрес внутри Tailscale. На сайте в поле сервера указывают `http://` этот адрес и порт `8787`, если не включали их HTTPS. Документация: https://tailscale.com/kb/1017/install и https://tailscale.com/kb/1242/tailscale-serve (HTTPS через `tailscale serve` без проброса порта).
- Cloudflare Tunnel: программа `cloudflared` на ПК сама устанавливает исходящее соединение, роутер не настраивается. Нужен свой аккаунт Cloudflare и имя. Документация: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/

Проброс порта на роутере и голый HTTP с телефона отправляют ключ входа открытым текстом. Для телефона нужен HTTPS из одного из вариантов выше. В `SMETA_ORIGINS` через запятую должен быть адрес сайта, по умолчанию `https://akinshinav.github.io`. Чужой сайт ответ сервера прочитать не сможет.

Пока домашний компьютер выключен, сервер недоступен. Правки копятся в браузере и уходят после входа, когда ПК снова включён. Два устройства, правившие одну и ту же смету врозь, увидят конфликт: местная версия остаётся, серверная не затирается, можно оставить свою отдельной копией или принять серверную.

## Ограничения

- Встроенный в Node модуль SQLite помечен авторами Node как экспериментальный. Он выбран, чтобы на Windows не собирать отдельные программы. Если модуль изменится, сервер придётся поправить.
- Сервер не считает геометрию и не печатает договор. Это делает страница.
- Вложений файлов, канбана, склада, заявок, типов помещений с отдельными ценами и импорта PDF нет.
- Старые сметы предыдущей схемы в новый список сами не переносятся. Их байты не стираются: при несовпадении схемы копия лежит в ключе `smeta_v1_library_damaged`. Файл старого экспорта можно импортировать, если в нём целые сметы.
- Второй вариант сайта `preview-v2` этим сервером не пользуется.
